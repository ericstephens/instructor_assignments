# Interface Contract: DB Layer → API Layer

This document defines the boundary between `src/db` and `src/api`. The API layer **imports only** from `src/db` — it must not reach into `src/api` from `src/db` (no circular deps).

---

## What the DB Layer exposes to the API

### Session factory

```python
# src/db/config.py
from src.db.config import get_db, SessionLocal, engine
```

- `get_db()` — generator yielding a SQLAlchemy `Session`. Use as a FastAPI dependency.
- `engine` — for Alembic and test setup only.

---

### Models (SQLAlchemy ORM)

```python
from src.db.models import (
    Event, EventDate, Instructor, Allocation, Availability,
    RoleEnum, ShiftDuration, CatalogStatus
)
```

| Model | Table | Key fields |
|---|---|---|
| `Event` | `events` | id, title, duration, min_primary_instructors, min_secondary_instructors, max_students, location, catalog_status |

| `Availability` | `availabilities` | id, instructor_id, start_time, end_time, is_available |

## Business rules the API must enforce

The DB layer enforces structural constraints (unique keys, FK integrity). The **API layer is responsible** for these rules:

| Rule | Where to enforce |
|---|---|
| An instructor can only be in one event_date at the same time slot | `POST /allocations` — query Allocation for instructor across overlapping event_dates |
| Each EventDate requires exactly one lead instructor | `POST /allocations` with role=lead — check no existing lead on that event_date |
| Minimum primary/secondary instructors per EventDate | Surfaced via `GET /event-dates/{id}/staffing-status` |
| `shift_duration` must be 4 or 8 | Pydantic schema validation |
| Max students per Event | `POST /event-dates/{id}/students` |
| Cannot allocate to a cancelled EventDate | Add `is_cancelled` field to EventDate, check in API |

## API endpoints to implement (from spec §5.2)

### Events
- `GET /events` — list with filters: `status`, `location`, `date_from`, `date_to`
- `GET /events/{id}` — single event with event_dates
- `POST /events` — create event
- `PUT /events/{id}` — update event
- `POST /events/import` — import catalog (body: `mode=replace|append`, file upload)

### Event Dates
- `GET /event-dates` — list with filters: `event_id`, `date`, `instructor_id`
- `GET /event-dates/{id}` — single event date with allocations
- `POST /event-dates` — create event date
- `GET /event-dates/{id}/staffing-status` — returns: lead assigned, primary count vs min, secondary count vs min

### Instructors
- `GET /instructors` — list all
- `GET /instructors/{id}` — single instructor with allocations
- `POST /instructors` — create instructor
- `GET /instructors/{id}/availability` — availability blocks
- `POST /instructors/{id}/availability` — add availability block

### Allocations
- `GET /allocations` — list with filters: `event_date_id`, `instructor_id`
- `POST /allocations` — create allocation (enforces conflict + lead uniqueness rules)
- `DELETE /allocations/{id}` — remove allocation

### Reports
- `GET /reports/instructor-history` — params: `instructor_id`, `date_from`, `date_to`
- `GET /reports/class-schedule` — params: `date_from`, `date_to`, `location`

## DB Agent deliverables (Phase 1)

Before the API Agent starts, the DB Agent must deliver:

1. `src/db/models.py` — all models correct, no bugs
2. `src/db/config.py` — single `Base`, env-var driven `DATABASE_URL`
3. `src/db/alembic.ini` + `src/db/migrations/` — Alembic configured and initial migration generated
4. `src/db/requirements.txt` — pinned dependencies
5. `src/db/tests/test_models.py` — all tests pass against real PostgreSQL (`instructor_test_db`)
6. All `__init__.py` files present for relative imports

## API Agent deliverables (Phase 2)

Before the Frontend Agent starts, the API Agent must deliver:

1. All endpoints listed above implemented in `src/api/routers/`
2. Pydantic schemas in `src/api/schemas.py`
3. Business rule enforcement (double-booking, lead uniqueness, min staffing check)
4. `src/api/tests/` — pytest suite covering all endpoints, hitting real PostgreSQL
5. `GET /openapi.json` auto-generated by FastAPI (no extra work needed)

## Frontend Agent deliverables (Phase 3)

1. React app in `src/frontend/` using Vite
2. FullCalendar.js for calendar view
3. Instructor self-allocation flow
4. Admin allocation + class management views
5. Vitest component tests
